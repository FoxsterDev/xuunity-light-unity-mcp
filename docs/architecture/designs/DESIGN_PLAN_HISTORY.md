## Purpose

This file tracks public-safe MCP design plans, their implementation status, and
the closeout evidence that proved or constrained the work.

Use this index when a chat produces a concrete MCP implementation plan,
retro-derived action plan, or non-trivial operator-surface design. The plan may
live as a dedicated design note under `docs/architecture/designs/` or as a
retro action plan under `docs/archive/retros/`, but this history should link it
and state what happened.

## Status Vocabulary

- `design`: approved direction exists, implementation has not started.
- `implementing`: work is in progress.
- `implemented`: code/docs/tests landed for the intended scope.
- `partially implemented`: useful subset landed, known scope remains.
- `validated`: implementation passed the intended test or smoke evidence.
- `superseded`: replaced by a narrower or newer plan.
- `moved`: design moved to another module or layer.

## Required Plan Record

For each substantial plan, keep a public-safe record with:

- title and date
- source retro, chat, or design input when relevant
- status and owner layer
- planned public interfaces or docs
- implementation checklist
- validation evidence
- post-implementation self-review
- post-retro notes: what went well, what was risky, and what follow-up remains

Do not include project-private paths, product names, credentials, request ids,
or consumer-specific evidence in public `AIRoot` records. Keep those in
project-local or host-local outputs.

| 2026-07-30 | `XUUNITY_MCP_REFERENCE_DRIVEN_UI_ACCEPTANCE_DESIGN_2026-07-30.md` | `P0.1, P0.2, P1.1, P1.2, P1.3, P2.1, P2.2, P2.3, P3.1, P3.2 implemented and validated` | From the 2026-07-30 reference-driven UI retro. Live/mixed data without a recorded payload hash, an unfrozen clock, an unpinned locale, or caller-asserted evidence downgrade `visual_determinism` and forfeit `decision_ready` automatically. Nodes are flat (path/parent_path) because JsonUtility cannot serialize recursion; uGUI and TextMeshPro readers live in constraint-gated satellite assemblies so the core keeps zero package references and a project without com.unity.ugui still compiles as `semantic_ui_partial`. Validated in Unity 6000.0.58f2: 47 EditMode package self-tests green with ugui, core-only compile green without it; the editor run caught an InternalsVisibleTo gap and a reader/alpha ordering bug. P1.3 joined the two lanes: `compare` takes `uiSnapshotPath`, maps Unity's bottom-left capture pixels to top-left reference pixels with the transform recorded in the payload, and gives each failed region `explained_by` (ranked nodes, suspicions, likely_cause, plain-language summary); declared `requiredUi` selectors now decide a real semantic lane that can fail a pixel-perfect capture. P1.2 added `unity_prefab_render` (isolated preview scene, controlled Canvas, declared viewport + safe area, no app boot, returns PNG plus its own render-space snapshot). P2.1 added `unity_prefab_mutate` (typed Editor-API transaction, preview by default, atomic rollback, post-mutation binding validation, reversible inverse patch, no object-reference writes so components cannot be type-swapped). P2.2 added `unity_ui_click` (EventSystem delivery to a unique selector with seven pre-delivery refusals). P2.3 added the device lane (`captureLane` + device descriptor; Game View never claims device parity). Validated in Unity 6000.0.58f2: 70 EditMode package self-tests green with ugui (render pixels verified separately with a graphics device, 11/11), core-only import green without ugui; 575 host tests green. P3.1 added the AI-vision lane (`xuunity.ui-vision-review.v1`): `unity_ui_vision_packet` renders a side-by-side sheet (reference left, candidate right, shared panel height, failed regions outlined on both panels) and ships a rubric; `unity_ui_vision_submit` records the judgement. The review is hash-bound to one image pair and expires as `vision_packet_stale` when either image changes, every required criterion needs a score plus a stated observation, the overall score is clamped to worst-required+1 so a strong claim cannot outrun a weak part, judge role is recorded (a self-review by the authoring agent is counted but permanently flagged), and numeric scores are withheld from the packet by default to avoid anchoring. The bar moves with the tolerance profile and is overridable per reference via `visionPolicy`; no profile requires the top score. `lane_disagreement` names which lane to trust: grid-pass with review-fail is `vision_contradicts_similarity` and fails the comparison, grid-fail with review-pass is `similarity_may_be_over_strict` and names the looser profile matching the observed similarity. P3.2 made the interaction lane real: a `ui_click` scenario step delivers a guarded click in a Play-mode scenario and emits a `xuunity.ui-interaction.v1` receipt, `required_interactions` on the reference decides the lane, and `compare` reads it from `interactionResultPath` defaulting to `fixtureResultPath` so one Play-mode run proves both. Edit-mode delivery blocks the lane rather than passing it. Also fixed a latent looseness: an `optional` lane that ran and failed now fails the comparison; only `not_required` opts out. Validated on two Unity versions with identical results (2021.3.45f2 and 6000.0.58f2): 78 EditMode package self-tests, 77 passed, 0 failed, 1 correctly ignored without a graphics device (11/11 with one); core-only import green without ugui; 634 host tests ran, 621 passed with 13 platform skips (59 new). The round-trip test caught a real defect: storing the normalized review made every submission invalid on re-read, because the normalized record carries `contract_version` and not `schema_version`. Open: nothing from this retro. |

## Closeout Rule

After implementing a tracked plan:

1. update the plan status and implementation checklist
2. run a self-review over the code and docs touched by the plan
3. record validation evidence or explicit validation gaps
4. write or update a post-retro under `docs/archive/retros/` when the work came
   from a retro or exposed reusable lessons
5. update this history index before final closeout
