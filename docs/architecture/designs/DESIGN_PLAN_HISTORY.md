## Purpose

This file tracks public-safe MCP design plans, their implementation status, and
the closeout evidence that proved or constrained the work.

Use this index when a chat produces a concrete MCP implementation plan,
retro-derived action plan, or non-trivial operator-surface design. The plan may
live as a dedicated design note under `docs/architecture/designs/` or as a
retro action plan under `docs/archive/retros/`, but this history should link it
and state what happened.

## Status Vocabulary

- `design`: approved direction exists, implementation has not started.
- `implementing`: work is in progress.
- `implemented`: code/docs/tests landed for the intended scope.
- `partially implemented`: useful subset landed, known scope remains.
- `validated`: implementation passed the intended test or smoke evidence.
- `superseded`: replaced by a narrower or newer plan.
- `moved`: design moved to another module or layer.

## Required Plan Record

For each substantial plan, keep a public-safe record with:

- title and date
- source retro, chat, or design input when relevant
- status and owner layer
- planned public interfaces or docs
- implementation checklist
- validation evidence
- post-implementation self-review
- post-retro notes: what went well, what was risky, and what follow-up remains

Do not include project-private paths, product names, credentials, request ids,
or consumer-specific evidence in public `AIRoot` records. Keep those in
project-local or host-local outputs.

P3.1 added the AI-vision lane (`xuunity.ui-vision-review.v1`): `unity_ui_vision_packet` renders a side-by-side sheet (reference left, candidate right, shared panel height, failed regions outlined on both panels) and ships a rubric; `unity_ui_vision_submit` records the judgement. The review is hash-bound to one image pair and expires as `vision_packet_stale` when either image changes, every required criterion needs a score plus a stated observation, the overall score is clamped to worst-required+1 so a strong claim cannot outrun a weak part, judge role is recorded (a self-review by the authoring agent is counted but permanently flagged), and numeric scores are withheld from the packet by default to avoid anchoring. The bar moves with the tolerance profile and is overridable per reference via `visionPolicy`; no profile requires the top score. `lane_disagreement` names which lane to trust: grid-pass with review-fail is `vision_contradicts_similarity` and fails the comparison, grid-fail with review-pass is `similarity_may_be_over_strict` and names the looser profile matching the observed similarity. Edit-mode delivery blocks the lane rather than passing it. Also fixed a latent looseness: an `optional` lane that ran and failed now fails the comparison; only `not_required` opts out.
